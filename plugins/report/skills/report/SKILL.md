# 分析记录报告

把本次会话的分析过程整理成一份记录。参数 `html` 或 `md`，不给时问用户要哪种。

## 硬性约束

- 内容只来自本会话实际发生的查询、写回和结论。没做过的步骤不写，结论不确定就写“未确认”。
- 报告只写到本地 `./output/<样本名>/report.html` 或 `report.md`，不写进插件仓库。
- 本地报告可以写完整的地址、字符串、IOC；在对话里回复时只给文件路径和摘要，IOC 打码（例如 `1.2.3.x`、`ex***le.com`）。
- 样本哈希不发给任何外部服务。

## 收集内容

按下面的顺序从本会话里整理：

| 部分 | 内容 |
|------|------|
| 样本概况 | 样本简称、文件类型、架构、大小、编译时间（若查过）、一两句话定性 |
| 工具 | 用到的 *sql 插件及模式（CLI / UI）、其他插件 |
| 样本行为总流程 | 一张流程图：入口 → 各阶段 → C2/外传/持久化，**只画本会话确认过的行为** |
| 分析思路 | 一张流程图：这次怎么从分诊一步步走到结论（分诊→定位→还原→写回→结论），给复核的人一张路线图 |
| 分析步骤 | 按时间顺序：做了什么、用的命令、得到的关键结果 |
| 关键函数 | 地址、原名 → 新名、作用；外加一张调用关系流程图，节点用新名、**只连已确认的调用** |
| 写回统计 | 改名、注释、类型修改各多少处，是否已保存 |
| 关键字符串 / 配置 | 解密出的配置、C2、互斥体等 |
| 技术点 | 若本会话用过 `techniques`，列出技术点和 ATT&CK 编号，并链接 `techniques.html` |
| 检测规则 | 若本会话用过 `yara`，列出规则名并链接 `.yar` 文件 |
| 结论与待办 | 定性结论、未完成的分析点 |

## 生成

- `html`：读取本技能目录下的 `report.html` 模板，替换 `{{...}}`，表格行按实际数量增删，没有内容的部分整段删掉。三张图填模板里 `data-diagram` 的 JSON（格式同 `techniques` 插件「图示规范」），底部渲染器会自动画，不用手写 SVG、不联网。
- `md`：读取本技能目录下的 `report.md` 模板，同样处理。Markdown 没有内置渲染器，三张图用模板里已占位的 **mermaid** 代码块（`flowchart TD`）填，节点文案只用本会话确认过的事实。**mermaid 节点/边的文字一律加双引号**（`A["..."]`、`Q{"...?"}`、`-->|"..."|`），否则填进去的 `()`、`:`、函数名会让 mermaid 解析报错。
- 三张图（行为总流程、分析思路、关键函数调用关系）都只能用本会话实际发生的事实，未确认的行为/调用不画。
- `<样本名>` 用用户给的简称，不用哈希。
- 写完后在对话里给出文件路径和三到五行摘要。
