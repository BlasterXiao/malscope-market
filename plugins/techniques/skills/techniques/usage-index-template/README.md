# 技术点关联索引 · 模板

这是一个**可本地独立运行**的小页面：回答"哪个组织、哪个家族/样本用过某个技术点"，以及反过来"某个家族用过哪些技术点"。和 `library/*.md` 不一样——这里存的是样本专属的关联记录（组织、家族、日期、一句话证据），所以不进插件仓库。

## 第一次使用

1. 把 `usage-index-template/` 整个文件夹复制到你自己的样本分析工作区（例如和"家族类型-命令控制表"同一级目录），改个名字，比如 `技术点关联索引/`。**不要**留在插件仓库里，也不提交到 malscope-market。
2. 如果那个工作区还没有 git 仓库，建议 `git init` 一个，方便看历史和回滚。
3. 以后每次 `/techniques` 生成完 `techniques.html`，把路径记下来（可以让会话帮你记在 `./output/techniques-index-path.json` 里，避免每次都问）。

## 目录结构

```
技术点关联索引/
  index.html              页面本体,双击或用浏览器打开即可,不需要起服务器
  data/
    orgs.js                组织清单(可以和家族表共用同一套组织 id)
    techniques.js          技术点目录:id、名称、分类、ATT&CK、library 条目链接
    usage/
      <org>/<slug>.js       每个组织一个技术点一个文件,一个文件可以有多条记录(同组织多个样本都用过这个技术)
    manifest.js             列出要加载哪些 usage 文件,新增文件后在这里加一行
```

## 新增一条记录

1. 打开 `data/techniques.js`，确认这个技术点有没有登记过。没有就按 `_template-technique.js` 加一行 `FT2.addTechnique({...})`（id 用 `library/` 里对应 `.md` 的文件名 slug，保持一致，方便跳转）。
2. 在 `data/usage/<org>/<slug>.js` 里追加一条 `FT2.addUsage({...})`（文件不存在就新建，照抄 `_template-usage.js` 的字段）。**不写地址、哈希、域名、IP 这些 IOC**，只写:
   - `technique`：技术点 id
   - `org`：组织 id（和 `data/orgs.js`、家族表尽量用同一套 id）
   - `family`：家族/样本简称（不用哈希）
   - `date`：当天日期
   - `evidence`：一句话证据摘要，别超过一行
   - `link`：指向那份 `techniques.html`（同机器用相对或绝对路径都行；换机器就留样本简称，不强求可点开）
3. 如果这个文件是新建的，去 `data/manifest.js` 加一行路径。
4. 用浏览器打开 `index.html` 确认新记录显示出来、搜索能搜到。

## 为什么不写进插件仓库

- 插件仓库（malscope-market）是公开、可分发的方法论仓库，`library/*.md` 里明确要求"不能出现任何样本专属信息"。
- 组织/家族/样本这些关联是你自己分析工作的产出，应该和"家族类型-命令控制表"一样留在你的私有工作区里，按自己的节奏积累、按自己的意愿决定要不要分享。
- 两套索引刻意分开：家族表只收"家族→C2 指令"，这个索引只收"技术点→用过它的家族"，职责不重叠、互不依赖，新增一边不用碰另一边的文件。
