# DNS 隧道 / DNS Tunneling

- 分类：通信 / C2
- ATT&CK：
  - T1071.004 Application Layer Protocol: DNS（核对日期 2026-10-12）
  - T1572 Protocol Tunneling（核对日期 2026-10-12）

## 原理

受害主机所在网络通常禁止直接出网，但几乎都允许 DNS 解析。主机把查询发给内网 DNS 服务器，内网 DNS 服务器会替它向外递归解析，最终把查询送到攻击者控制的权威 DNS 服务器。样本把要外传的数据编码进查询的子域名里，攻击者服务器把指令放进应答记录（常见 TXT）里返回。受害主机和攻击者之间没有直接连接，数据借内网 DNS 这条合法通道来回传，所以叫隧道。

## 机制

- A：受害主机。能访问 B，**不能直接访问 C**（被防火墙拦截）。
- B：内网 DNS 服务器 / 递归解析器。能访问外网 DNS。
- C：攻击者控制的权威 DNS 服务器，负责某个域名（如 `x.attacker.example`）。
- 上行：A → B 发送查询 `<编码后的数据>.x.attacker.example` → B 递归到 C。
- 下行：C 在应答记录里放指令 → B → A。
- 被阻断：A → C 直连。

## 常见实现

- 系统 API：`DnsQuery_A` / `DnsQuery_W` / `DnsQueryEx`（dnsapi.dll），或 `getaddrinfo` / `gethostbyname`（只能走 A/AAAA 记录）。
- 自建报文：`socket` + `sendto` / `recvfrom` 直连 UDP 53 端口，自己拼 DNS 报文头。
- 记录类型：TXT（类型值 16，0x10）最常见，也有 A、AAAA、CNAME（5）、NULL（10）、MX。
- 编码：Base32（不区分大小写，适合域名）、Base64 变体、十六进制。
- 长度限制：单个标签最多 63 字节，完整域名最多 253 个字符，所以数据会按 63 字节左右分段。
- 会话管理：子域名里常带序号、会话 ID、校验字段，防止缓存和乱序。

## 在样本里怎么找

- 查 `DnsQuery_*`、`DnsQueryEx`、`sendto`、`recvfrom` 的交叉引用，看调用者是谁。
- 搜 Base32 字母表 `ABCDEFGHIJKLMNOPQRSTUVWXYZ234567` 或 Base64 字母表。
- 搜常量：53 / `0x35`（端口）、16 / `0x10`（TXT 类型）、63 / `0x3F`（标签长度上限）。
- 看拼接域名的函数：循环里按固定长度切分、插入 `.`、拼接固定后缀。
- 看应答解析：取 TXT 记录内容后紧跟解码和命令分发。

## 检测要点

- 网络侧：同一域名下大量一次性子域名；子域名长度长、字符熵高；TXT 查询比例异常；单主机 DNS 查询频率和数据量异常。
- 主机侧：非浏览器、非系统服务进程频繁调用 DnsQuery；进程直接向 53 端口发 UDP 包而不走系统解析器。
- 样本侧：编码函数和分段拼接函数的指令序列、固定的域名后缀构造逻辑，可交给 `yara` 插件写规则。
