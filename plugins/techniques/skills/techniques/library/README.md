# 技术点库

通用技术点说明，跨样本复用。**只写通用知识，不写任何样本专属信息**（地址、哈希、域名、IP、互斥体名），可以公开。

写给两种读者：正在写样本 techniques.html 的会话（找原理和证据思路），以及正在学这门技术的人（想看懂机制、能自己动手试一次）。所以每条都要能单独拿出来当教程读，不是只给会话抄的速查卡。

## 条目格式

文件名用英文短横线 slug，例如 `process-hollowing.md`。内容按下面的结构写：

```markdown

- ATT&CK：<编号> <官方英文名>（核对日期 YYYY-MM-DD）
- 关联技术：[[其它 slug]]（可选，常搭配出现或容易混淆的技术）

## 攻击者面对的问题
1 到 3 句：不用这个技术会怎样、受到什么限制（网络策略、EDR、字符串扫描……）。

## 核心思路
1 到 3 句：这个技术具体绕开了上面哪条限制，走的是哪条路。

## 分步拆解

（一次系统调用、一次网络请求、一次内存写入），不是"进行编码""完成注入"这种抽象词。

## 技术点关联索引（谁用过这个技术）

这类关联记录（组织 → 家族/样本 → 技术点 → 日期 → 一句话证据）存在**本仓库之外**的私有位置，用 `usage-index-template/` 里的引擎生成一个可本地查询的页面，像这样用：

- 第一次用：把 `usage-index-template/` 整个复制到你自己的样本分析工作区（不要留在插件仓库里，也不提交到这个 marketplace），当作一个独立的本地小仓库。
- 之后每次 `/techniques` 生成完一份 `techniques.html`，追加一条使用记录（技术 slug、组织、家族/样本、日期、一句话证据、指向那份 techniques.html 的路径），不改动已有记录。
- 查询时打开那个本地 `index.html`：按技术点能看到所有用过它的组织和样本；按组织能看到它用过的所有技术。
