# 技术点提取与记录

把本次分析过的样本用到的技术一个个拎出来，写成一份 HTML 详细记录。

## 硬性约束

- **证据只来自本会话的查询结果。** 地址、API、字符串、常量必须在本会话里由 *sql 插件查出来过。证据不够时，先用已连接的 *sql 插件补查；补不到就标“待核实”，不要编。
- **ATT&CK 编号必须核对过。** 优先用本技能 `library/` 里已核对的编号。新编号要打开 `https://attack.mitre.org/techniques/<编号>/` 核对名称（只访问 ATT&CK 公开页面，不发送任何样本信息）；无法联网时在编号后标“（未核对）”。
- 不执行、不调试样本。
- 记录只写到本地 `./output/<样本名>/techniques.html`，不写进插件仓库。

## 第 1 步：列出候选技术点

从本次分析结果里找，按 ATT&CK 战术分类：

| 分类 | 常见线索 |
|------|----------|
| 执行 / 注入 | `VirtualAllocEx` + `WriteProcessMemory` + `CreateRemoteThread`、APC、傀儡进程 |
| 持久化 | Run 键、计划任务、服务创建、启动目录 |
| 防御规避 | API 动态解析 / 哈希、字符串加密、反调试、反虚拟机、白加黑侧载 |
| 发现 | 主机名、用户名、进程列表、网络配置收集 |
| 通信 / C2 | 自定义协议、HTTP(S)、DNS 隧道、域前置、代理链 |
| 收集与外传 | 截屏、键盘记录、文件打包、分块外传 |

列出候选后给用户看一眼清单（名称 + 一句话依据），用户确认或增删后再写详细内容。

## 第 2 步：查技术点库

本技能目录下的 `library/` 是通用技术点库，`library/README.md` 有索引。

- 库里有的技术点：沿用它的原理、机制图结构和 ATT&CK 编号，只补本样本的证据和差异。
- 库里没有的：按 `library/README.md` 的格式新写一条草稿，保存到 `./output/library-drafts/<slug>.md`，最后提醒用户把草稿复制进仓库的 `plugins/techniques/skills/techniques/library/` 再提交。草稿里不能出现任何样本专属信息（地址、哈希、域名、IP）。

## 第 3 步：每个技术点写一张卡片

| 部分 | 要求 |
|------|------|
| 名称 / 分类 | 中文名 + 常用英文名，分类见第 1 步 |
| ATT&CK | 编号 + 官方英文名，可多个 |
| 原理 | 3 到 6 句：攻击者面对什么限制、用这个技术绕过了什么、数据或控制流怎么走 |
| 机制图 | 内联 SVG，见下方画法 |
| 样本证据 | 表格：证据描述 / 地址或位置 / 来源查询（写用到的插件命令，如 `/idasql:xrefs`） |
| 本样本的实现细节 | 和库里通用描述不同的地方：编码方式、密钥、记录类型、分段长度等 |
| 检测要点 | 网络侧、主机侧、样本侧各写能写的；样本侧可以交给 `yara` 插件 |

### 机制图画法

- 用内联 `<svg>`，参与方画成方框（主机、服务器、进程、注册表等），箭头上写清动作（“查询”“写入”“注入”）。
- **被阻断的路径**用红色虚线，并在路径中间画一个叉，例如 DNS 隧道里 A 不能直连 C。
- 文字和线条用 `currentColor`，填充用模板里的 CSS 变量（`var(--card)`、`var(--sun)` 等），这样深浅色主题都能看。
- 一个图只说明一个机制，不画无关的组件。

## 第 4 步：生成 HTML

1. 读取本技能目录下的 `record.html` 模板。
2. 填写页头：样本名、分析日期、使用的 *sql 插件、技术点数量。
3. 填写“技术点总览”表：每个技术点一行。
4. `<!-- CARD:START -->` 到 `<!-- CARD:END -->` 之间是一张卡片的模板，每个技术点复制一份并填写，最后删掉模板注释。
5. 写到 `./output/<样本名>/techniques.html`。`<样本名>` 用用户给的简称，不用哈希。
6. 在对话里只给出文件路径和技术点清单（名称 + ATT&CK 编号），不要在对话里贴完整 IOC。
